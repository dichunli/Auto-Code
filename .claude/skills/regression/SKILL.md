# 一键回归测试技能

项目已有的测试脚本分散在多个命令里，本技能统一入口，按从快到慢的顺序执行，任一失败立即停下报告。

## 前置条件检查

```bash
npx pm2 list
curl.exe -s -o /dev/null -w "%{http_code}" --max-time 10 http://localhost:3000/login
```

服务没在跑 → 先提示用户"服务未启动，是否先执行 /部署？"，不要擅自部署。

## 执行顺序

### 第 1 组：单元测试（最快，不依赖服务）
```bash
npm run test:unit
```

### 第 2 组：冒烟测试（登录 + 工单 + 数据保存）
```bash
SMOKE_ACCOUNT=19900001111 SMOKE_PASSWORD=test123456 npm run test:smoke
```

### 第 3 组：流程测试（核心业务流程）
```bash
npm run test:flows
```

### 第 4 组：权限测试（角色权限边界）
```bash
npm run test:perm
```

## 汇报格式

```
========== 回归测试报告 ==========
单元测试：✅ 通过（xx 个用例）
冒烟测试：✅ 通过
流程测试：❌ 失败 —— 开单流程第 3 步超时
权限测试：⏭️ 跳过（前置失败）
==================================
结论：不通过，先修复流程测试再交付
```

## 红线

- 前一组失败，后面的标记"⏭️ 跳过"，不要继续跑（失败会连锁）
- 禁止把失败的测试说成"基本通过"
- 如果失败原因疑似测试脚本本身过时（而不是业务 bug），要明确指出并建议修脚本
