## 一、架构 · 客户端直写写操作

> 项目规范要求核心写操作走 Server Action（`"use server"` 文件），禁止客户端组件直接 `supabase.from().insert/update/delete/upsert`。以下为尚未收口的部分。

| 问题 | 现状 | 风险/影响 | 优先级 | 建议方案 | 状态 |
|------|------|----------|--------|----------|------|
| ⚠️ 客户端直写写操作共 422 处 | insert 178 / update 189 / delete 53 / upsert 2，分布在 141 个文件，集中在 `src/components`（145 处工单编辑器生态） | 登录过期/网络闪断时保存失败或数据对不上 | 高 | 按模块分批收口为 Server Action | 待做 |
| ⚠️ 其中高危 213 处 | 动钱（预收款 `advance_payment_records`、财务流水、外包金额）、动库存（配件数量、退货扣减 `part_batches`/`parts`）、工单结算与状态、53 处 delete | 钱算错、库存对不上 | 高 | 优先收口：金额/库存/结算/删除 | 待做 |
| 手写 setTimeout 防抖 12 处 | 分布 6 个文件（`m/reception/new/page.tsx`、`parts/new` 系列、`VehicleForm.tsx`、`PartGroupHeader.tsx` 等） | 违反规范，防抖逻辑不统一 | 中 | 改用 `useDebounce`（`src/lib/useDebounce.ts`） | 待做 |
